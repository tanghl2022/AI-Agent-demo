# ADR-003：采用 Tool Calling 处理动态业务能力调用

## 状态
Accepted

## 背景
WMS Agent 已具备意图识别、库存查询、库位查询等能力。随着库存分析场景增加，单纯依赖意图路由到固定 Node 无法高效表达“先查询库存，再根据结果决定是否查询预占、订单或库存流水”的动态过程。

## 决策问题
业务能力调用由 Graph 完全硬编码，还是允许专业 Agent 使用 Tool Calling 动态选择能力？

## 可选方案

### 方案 A：Graph 硬编码全部调用路径
优点：
- 可预测
- 执行路径清晰

缺点：
- 分支会快速增加
- 每增加分析策略都需要修改 Graph
- 难以利用 LLM 根据上下文动态规划查询

### 方案 B：Tool Calling
优点：
- Agent 可以根据上下文动态选择 Tool
- 更适合多步骤分析
- Tool 可以形成标准化能力目录

缺点：
- 必须做好 Tool 描述、参数校验、权限和调用边界
- 需要记录执行过程和证据

## 最终决策
采用 Tool Calling，但只用于确实需要动态决策的场景。

固定、确定性的业务流程继续使用 Graph/Node。

## 决策原因
Tool Calling 的价值不是替代所有 Node，而是让专业 Agent 在受控工具集合中自主决定下一步动作。

## 影响
逐步建设 Tool Registry，并按领域管理 Tool。第一阶段库存 Tool 包括库存、预占、冻结、入库、出库和库存流水等查询能力。

## 重新评估条件
如果某些 Tool Calling 流程实际始终按固定顺序执行，应将其重新评估为确定性工作流。
